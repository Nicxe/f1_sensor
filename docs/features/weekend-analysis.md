Start with the session overview, then choose a focused view for results, strategy or replay. The cards share F1 Sensor data, but each view depends on the timing or historical information available for the selected session.

## During a session

The [Weekend Hub](/cards/weekend-hub) brings session context, a timeline and analysis views together. Use it alongside [Race Lap](/cards/race-lap) or [Race Control](/cards/race-control) when you want a focused timing table or message feed.

## After the session

| Question | View |
| --- | --- |
| What was the classification? | [Results](/cards/results) |
| How did positions change lap by lap? | [Lap Position Progression](/cards/lap-position-progression) |
| How has the championship developed? | [Season Progression](/cards/season-progression) |
| What happened during a past session? | [Replay Control](/cards/replay-control) and [Replay Mode](/features/replay-mode) |

Use the Results card's archive controls for historical classifications. A classification can exist even when lap-by-lap data is unavailable. In particular, do not expect every Sprint result to include a lap-position chart.

## Read the data state

Wait for a complete result from the source. A waiting, unavailable or unsupported view explains a different condition from a finished session with no incidents. Do not infer missing events or a driver's performance from an empty panel.

Keep [No Spoiler Mode](/features/no-spoiler-mode) on until you want to reveal current results. Archived replay follows its own selected session; it does not turn protection off for you.

## Choose your layout

Start with one overview and one detailed card. The [card gallery](/cards/cards-overview) shows each card's image, requirements and settings so you can add the views you need.
